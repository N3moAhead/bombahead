# BombAhead

Welcome to BombAhead.

BombAhead is a bot competition platform for a Bomberman-style game. You write a bot with an SDK, package it as a container image, push that image to a registry, register it on the platform, and then it plays ranked matches against other bots.

## Important: use SDKs, not legacy examples

The folders `client_go/`, `client_js/`, and `client_rust/` in this repository are legacy examples and can be outdated.

For new bots, use the current SDKs.

## Competition flow

1. Build your bot with an SDK
2. Test locally against the game server
3. Build a container image for your bot
4. Push the image to a public registry
5. Add the image in BombAhead (`/bots/new`)
6. Let the platform schedule matches and track results

## What your bot container must do

At runtime, your container should start your bot process immediately.

Your bot should:

- Connect to `ws://localhost:8038/ws`
- Send `player_status_update` (`isReady: true`) after connecting
- Read game state messages and send actions every tick
- Support the `BOMBERMAN_CLIENT_AUTH_TOKEN` env var (SDKs handle this)

The match runner starts server and bot containers in one pod/network namespace, so `localhost:8038` is correct inside bot containers.

## Build and push your image

Example (Docker):

```bash
docker build -t docker.io/<username>/<bot-name>:<tag> .
docker login docker.io
docker push docker.io/<username>/<bot-name>:<tag>
```

Example (Podman):

```bash
podman build -t docker.io/<username>/<bot-name>:<tag> .
podman login docker.io
podman push docker.io/<username>/<bot-name>:<tag>
```

You can also use `ghcr.io/...` images.

## Register your bot on the platform

In BombAhead:

1. Log in
2. Open `/bots/new`
3. Fill in:
   - Bot name (required, max 30 chars)
   - Description (optional, max 500 chars)
   - Image URL (required), for example `docker.io/<username>/<bot-name>:<tag>`
4. Save

## Image requirements (critical)

Your image reference must be pullable by the match runner.

- Use a correct, fully qualified image name
- Ensure the repository/tag exists
- Ensure the image is public or otherwise accessible to the runner environment
- Avoid registry pull-rate issues (anonymous Docker Hub pulls can be limited)

If an image cannot be pulled, matches will fail before game start.

## Local testing

You can test locally by running:

- a server container
- one dummy opponent bot container
- your own bot

This validates connection handling, move loop, and basic behavior before pushing.

## After pushing: where to look

- `/bots` for your bot list
- `/bots/{id}` for bot details and per-bot match history
- `/matches` for global match list
- `/matches/{matchID}` for replay/history details

## Notes

- Matches are generated by the platform and processed asynchronously.
- Ratings/leaderboard update from match results.
- Keep tags immutable for reproducibility (for example `:v1.2.0` instead of always `:latest`).
